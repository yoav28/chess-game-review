# Chess.com Game Review investigation

Investigation date: 24–25 October 2026. Target: [Chess.com Analysis](https://www.chess.com/analysis). This document records the observed feature surface and the independent implementation requirements; it does not claim exact product parity.

## Evidence and boundaries

The public Analysis page was inspected in the Codex browser. Its shipped scripts were captured through CDP `Page.getResourceContent`, without signing in, into `/tmp/chess-com-rea-capture`. The capture manifest records `2026-10-24T12:15:27.153Z` and deployment `2026.10.3-hotfix.20ef972`.

REA analyzed that captured directory. Retained parent Evidence ID: `ev_be520a14fba478c2ba3b4e2a9e2fcee689a0178b6c0c7c1452858508b3f3d7eb`. REA target root SHA-256: `68e743f59543622d01b4cbdaee927400791a5f6dcc6cf29353e28b75d14ae698`.

Evidence types below distinguish interactive observations from shipped client code. A bundled control, identifier, or translation establishes a client feature surface; it does not establish that the feature is available for every account or that its server behavior was executed. The capture covers six scripts loaded by the public page, not every lazy-loaded bundle or server implementation.

### Recorded browser observations: initial public session

- The welcome flow describes accuracy, brilliant moves, blunders, best continuations, variations, and retrying mistakes.
- An Opera Game PGN was loaded into Analysis. The board, move navigation, and local engine analysis were usable.
- Analysis displayed Stockfish 19 Lite and three candidate lines.
- Opening Game Review required sign-in during this initial session. The original script capture therefore remains a public-session capture.

The welcome descriptions establish advertised functionality. These are interactive investigation notes; the six script captures provide the durable static evidence identified below.

### Recorded browser observations: subsequent signed-in session

The user subsequently signed in voluntarily. The same Opera Game PGN was reviewed at [Chess.com Game Review](https://www.chess.com/analysis/review), and an actual report completed. These later runtime observations supplement the public capture; they do not change its provenance or hashes.

- The report displayed White accuracy 96.1 and Black accuracy 63.3. Its move counts included three White Brilliant moves, one White Great move, and four Black Mistakes. These are observations for this game and engine run, not expected outputs for the independent application.
- The move-quality counts could be expanded and collapsed.
- Start Review opened the move-by-move presentation; Highlights returned to the overview.
- Explain played an animated continuation, and Got it returned to the review. An explanation of Black's `...e5` described occupying the center and freeing development routes.
- A coach audio toggle was present. Actual speech output was not established by observing that control.
- The final report for this unrated imported PGN did not visibly display Game Rating. Static REA extraction found the review client reading gated `gameRatingV2`, falling back to `effectiveElo`, handling a zero v2 value as insufficient moves, and marking legacy values. The exact [captured review script](https://www.chess.com/r2/client-packages/analysis/2026.10.3-hotfix.20ef972/tab-review.88a71be6.BWieoMcwwK.chunk.js) has SHA-256 `c414443c71229a54c231c38f68cacc0e547a56a28f926c1ca0f197e0f5acfd33`. This establishes UI field branches only: the formula and payload producer remain unresolved. A rated-report attempt on 24 October hit the account’s Daily limit; a later eligible report is recorded below.
- A later mistake-count selection jumped to `Bxf3`, labeled Mistake, with Explain and Best controls. No Retry control was visible in that account/view; this does not establish absence across accounts or flows. A successful Chess.com retry remains unobserved.
- Selecting `10.Nxb5`, then its Share icon, opened a dialog with a link/copy control and PGN, Image, Gif, and Embed tabs. Image displayed a downloadable chessboard image. Gif produced an actual 720 × 720 download with 34 frames for the 33-ply Opera Game, looping indefinitely; observed frame delays were 800/1400/2500/6000 ms.
- Embed displayed hosted iframe markup, a forum diagram code, Board/Pieces choices, and Coordinates/Puzzle checkboxes. A subsequent puzzle inspection exercised legal incorrect e3, Reset, origin-square Hint, correct e4, the automatic e5 reply, and Solution revealing the full recorded move list. A later generated diagram rendered the selected Icy Sea board and Book pieces; publication on another site remains unverified. No external message or public post was sent.

This confirms a signed-in report and the listed interactions. It does not establish all account tiers, coach personalities, move categories, scoring formulas, or review branches.

### Further desktop controls and rated-report attempt

On 25 October, a rated 5-minute account game completed review after the previous day’s limit. Its report visibly displayed Game Rating values of 1350 and 1300 in the on-screen player order. This confirms that the field appears for at least one eligible rated report. A single output does not reveal how the ratings were calculated; the formula and payload producer remain unresolved.

Subsequent Codex-browser inspection exposed these controls without establishing that every option or engine executed:

- Game Review showed Torch Human selected, with Stockfish also offered. Fast was selected; Standard was selectable; Deep and Maximum were disabled in the inspected account/view.
- The surrounding Analysis settings offered Stockfish 19, Stockfish 19 Lite, Torch 4, Torch 4 Lite, and Off; line counts 1–5; a Threads stepper showing 2; and **Maximum Time**, with 3/5/10/20/30 seconds and Unlimited choices. These are time choices, not maximum-depth choices.
- Interface settings included arrows, classifications, explanation autoplay/delays of 1/3/5/7/10 seconds, avatar, course/recommendation visibility, and move-time display.
- A second, rated 77-ply Toxicmybrother–MagnusCarlsen game was submitted for Game Review. The account displayed **Daily limit reached**; no second report or Game Rating was produced. This is a verified account-limit boundary, not proof that Game Rating is absent from eligible reports. No quota or access restriction was bypassed.

Open File now has one to five Stockfish lines, independent presentation profiles, and a subset of corresponding display/playback settings. Position analysis supports one to eight hardware-available threads, 3–30 second searches, Unlimited search, streaming results and a Stop action. Full-game review uses its separate single-thread budget. The other engines, premium strengths, proprietary personalities, and identical setting semantics remain unimplemented.

The application tested Unlimited with two threads through one minute of active browser analysis, stopped at depth 37 and retained its complete lines. Position analysis and full-game review can both select the threaded Lite build. Full-game reviews remain time-bounded, record their thread count in the saved engine description, and default to one thread.

### Public product documentation

The [official Game Review guide](https://support.chess.com/en/articles/8584089-how-does-game-review-work) was also inspected in the Codex browser. It documents the report, coach/explanation and retry flow. This is product documentation, not evidence that every branch was exercised in the captured session. The independent retry now checks a different legal attempt with fresh engine analysis rather than rejecting it solely because its UCI differs from the saved best move.

The [official Game Rating explanation](https://support.chess.com/en/articles/10773754-how-is-game-rating-calculated-in-game-review) gives a qualitative description; it does not publish a recoverable calibration formula. The independent application does not invent a Game Rating.

The [official accuracy guide](https://support.chess.com/en/articles/8708970-how-is-accuracy-in-analysis-determined), updated June 21, 2025, says current Chess.com accuracy uses CAPS2 and that its math differs from CAPS. It describes the goal qualitatively but publishes no formula. Open File's Lichess-based v2 therefore remains a separate, explicitly labeled model; it is not represented as a CAPS2 approximation.

## Reconstruction boundary

The application uses independently written source, original SVG piece artwork, its own interface, chess.js standard legality, the chessops-backed Chess960/three-check adapters, and separately distributed Stockfish and Fairy-Stockfish engines. The chessops GPL-3.0-or-later license and source information are included with the static application. Captured Chess.com scripts, proprietary assets, coach media, source excerpts, and the capture directory must not be committed into the application repository. The investigation informs a feature specification; it does not supply implementation code.

The signed-in Opera Game report and listed interactions are runtime-observed. Proprietary scoring formulas, a successful Chess.com retry, Game Rating in an applicable source report, every account/locale/experiment branch, and complete server behavior remain unresolved. Independent import, standard/Chess960 review, practice, and tablebase checks prove only the recorded implementation flows. They do not establish every feature or server branch in the source product. The latest additions remain local and have not replaced the earlier private deployment.
